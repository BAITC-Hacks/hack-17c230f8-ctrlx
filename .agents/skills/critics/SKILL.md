# Critics: свежие глаза на свою зону

Автор ангажирован к своему коду и не видит своих ошибок. Критики работают со свежим контекстом и знают только задачу, контракт и твою зону.

1. Зона: `scripts/team.sh whoami`. Объём — файлы зоны, изменённые с начала хакатона: `git diff --stat $(git rev-list --max-parents=0 HEAD) -- <пути зоны>`.
2. Запусти **параллельно** четырёх критиков со свежим контекстом (Claude — субагенты, модель подешевле; Codex — его субагенты, если доступны, иначе по очереди). Каждому дай `docs/TASK.md`, `docs/REQUIREMENTS.md` (R-ID и контракт) и пути зоны. Каждый возвращает ≤ 5 находок: «файл:строка — проблема — исправление — крит / важно / мелочь», без воды.
   - **Логика**: поведение против контракта и приёмки R-ID, необработанные ветки, форматы данных, падения на пустом или кривом вводе.
   - **Безопасность**: секреты в коде, персональные данные уходят в LLM или логи без маскирования, инъекции (SQL, промпт), нет валидации входа, ключи на клиенте.
   - **Простота**: лишний и дублирующийся код, мёртвые ветки — то, что можно удалить без потери функции.
   - **Требования и демо**: какие must R-ID не выполнены или не показываются в демо, работает ли DEMO-режим без ключа, что жюри увидит за первые 30 секунд.
   Вместо своих промптов можно взять встроенные: Claude — `/code-review` (логика) и `/security-review`; Codex — `codex review`.
3. Сведи находки в одну таблицу по серьёзности. Исправь критичное и важное **в своей зоне**. Чужое — строкой в «Нужно от других» своего `docs/tasks/<id>.md` и сказать человеку. Мелочи после 16:30 не трогай.
4. Итог — в свой `docs/tasks/<id>.md` → «Готово»: «critics: найдено N, исправлено M»; владелец README перенесёт в `docs/TESTING.md`.
5. `scripts/checkpoint.sh "fix: critics findings (R-…)"`.
