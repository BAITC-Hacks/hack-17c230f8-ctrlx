# Agentic AI: проверяемый контур принятия решений (R5, R9)

WindCast состоит из числовой модели, детерминированного адаптивного оркестратора и
необязательного LLM-супервизора. У каждого слоя своя проверяемая ответственность.

| Слой | Что решает | Доказательство |
|---|---|---|
| Модель | Мощность и интервал станции по доступной погоде | отложенные месяцы и эталоны в `outputs/metrics/` |
| Оркестратор | Допустимость данных, запасная модель, пересчёт будущих часов | `agent_log.jsonl`, replay и fault-сценарии |
| LLM-супервизор | Какие проверки запросить и направить ли выпуск на ручную проверку | `supervisor.json`: реальные function calls, наблюдения, disposition |

Супервизор получает агрегаты одного уже рассчитанного выпуска. Он выбирает
`quality`, `weather`, `revisions`, читает ответы инструментов и затем вызывает
`finish`. `accepted` означает принятие супервизором для просмотра диспетчером,
а не подачу торговой заявки: интеграции с торговой площадкой нет.
`review` создаёт проверяемую отметку необходимости ручного разбора в JSON.
Это отдельный диагностический цикл, не LLM-управление обучением или числовым прогнозом.

Программа требует изучить качество и погоду, а при пересчёте — также изменения.
Предупреждения, запасная модель или отсутствие погоды принудительно дают `review`,
даже если LLM предлагает `accepted`. Непрочитанные свидетельства не принимаются.
Произвольные команды, пути, даты и новые числовые прогнозы инструменты не принимают.
Ошибка провайдера или неверный вызов сохраняет прогноз и завершает супервизор
консервативным результатом. Отсутствие ключа даёт детерминированное решение.

## Как воспроизвести

Без ключа:

```bash
DEMO_MODE=1 uv run python -m app.cli forecast --issue 2026-01-31 --supervise --demo-dir runs/supervisor_demo
```

С ключом: настроить локально переменные из `.env.example` (`DEMO_MODE=auto`,
`LLM_API_KEY`, `LLM_MODEL`, `LLM_BASE_URL`), затем выполнить:

```bash
uv run python -m app.cli forecast --issue 2026-01-31 --supervise --demo-dir runs/llm_demo
```

Читать `runs/llm_demo/runs/<run_id>/supervisor.json`. Только `mode=llm` и непустой
журнал подтверждают успешный живой LLM-цикл. Моки тестов и `mode=demo` таким
подтверждением не являются. `--llm` отдельно включает текстовую сводку; её
проверка чисел ограничена принадлежностью значения набору фактов и не доказывает
семантическую правильность каждого предложения.

Используется OpenAI-совместимый native function calling, поэтому можно настроить
OpenAI или совместимый NVIDIA endpoint с моделью, поддерживающей tools.
Клиент ограничивает число раундов и токены ответа, отключает сетевые повторы,
использует таймаут и резервный провайдер. Кредиты не нужно расходовать полностью.
В опубликованных правилах обязательного расходования выданных кредитов нет.

## Позиционирование для первого этапа

Основная ценность — воспроизводимый прогноз с контролем того, что было известно
на момент выпуска, и восстановление после отказов. Сильное доказательство —
исправление входа/выхода на реальном тестовом сценарии и объяснение принятого решения.
Качество модели и польза оркестратора измеряются отдельно. Сам факт вызова LLM
не доказывает улучшение точности, а уменьшение MAE не доказывает агентность.

До дедлайна нужно сохранить числовые результаты, журнал решений, сценарии отказа
и описание воспроизведения. Для Demo Day используются эти же артефакты и версия
проекта; будущие улучшения модели не входят в текущий результат.

## Обучение и ограничения интервала (R1, R3, R7)

Метка мощности станции требует наблюдения обеих равномощных турбин. Пропуск
одной турбины не подменяется выработкой другой. Медиана станции обучается отдельно:
медиана среднего не обязана совпадать со средним медиан отдельных турбин.

Квантили имеют собственные признаки кривой мощности, обученные до начала
калибровки. Из обучения квантилей исключены целевые часы периода калибровки,
включая пересечение 48-часовых горизонтов соседних выпусков. Калибровочный сдвиг
использует конечновыборочную порядковую статистику. Это устраняет найденное
смешение обучающих и калибровочных данных, но корреляция временного ряда остаётся:
универсальная гарантия 80-процентного покрытия не заявляется.
Метаданные модели сохраняют границы разделения. Старые pickle загружаются для
совместимости; исправление начинает действовать в результатах после `train`
и повторных `evaluate`, `backtest`, `replay`, `faults`.

Примечание R9: команда отдельно сохранила в `runs/llm_demo/` пример текстовой
сводки OpenAI (`--llm`, до последнего переобучения). Это исторический пример
работы текстового клиента, не доказательство запуска native-tool супервизора
и не оценка точности текущей модели. Новые внешние API-вызовы отложены.
