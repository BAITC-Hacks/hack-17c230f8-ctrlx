# Журнал проверок

Что проверяется, чем и с каким результатом. Владелец файла — `ansar`.

## Команды

```bash
uv run pytest -q          # все тесты
uv run ruff check .       # линтер
scripts/smoke.sh          # свежий clone с GitHub → install → тесты → запуск → основной сценарий
```

`scripts/smoke.sh` проверяет коммит с GitHub в отдельном клоне. `scripts/smoke.sh --local` проверяет текущий локальный коммит, без незакоммиченных правок.

Последовательность: установка по lock-файлу → SHA-256 исходных CSV и погодного кэша → удаление готовых модели/прогнозов/обработанных данных только в клоне → обучение с нуля → 28 выпусков → проверка 672 часов → все тесты и линтер → HTTP-проверка всех выпусков и журналов. При первой ошибке скрипт завершается ненулевым кодом и показывает путь к логу. ОС, Python, коммит и дата записываются в `environment.txt`, результат — в `result.txt`. Рабочая копия не изменяется. Установка требует сеть или предварительно заполненный кэш пакетов; расчёт использует погодный кэш без ключей.

## Проверки без автотестов

- **Происхождение погоды.** Раскрываемая таблица показывает источник, архивное поле и модель каждого часа новейшей ревизии. Окраска графика — визуализация выбранного поля, не доказательство отсутствия утечки. Доступность проверяется кодом и тестами по принятому правилу задержки; точное историческое время публикации не сохранено в строках прогноза.
- **Пересчёт при обновлении данных.** Выпуск с ревизией 1 рисуется сплошной линией, а то, что он заменил, — пунктиром, с отметкой «пересчёт t0+12 ч». Видно, на сколько изменился прогноз.
- **Работа без ключей.** `/api/health` отдаёт `"mode":"demo"`, на странице значок `DEMO`. Ни одно число прогноза от LLM не зависит.

## Известные расхождения

- В сводке из `report.md` строка «Предупреждения: 6» считает **часы**, а блок на странице «Шаги агента с замечаниями: 1» считает **шаги лога**. Это разные сущности, не ошибка; подписи разведены, чтобы числа не читались как противоречие.

## Приёмка интерфейса R8

- Быстро переключить несколько выпусков: дата, график, сводка и журнал должны принадлежать одному выпуску. Во время загрузки старые значения очищаются, экспорт заблокирован.
- Раскрыть «Происхождение погоды по часам»: 48 целевых часов, источник и поле каждой строки. Отсутствие ветра показано прочерком.
- Переключить парк/турбины: коридор p10–p90 относится только к парку.
- Скачать CSV: все исходные строки и ревизии, нормализованная мощность 0…1, локальное время с UTC-смещением и UTC; это не торговая заявка.
- При недоступном журнале статус «Требуется проверка»; резервный путь явно обозначен. «Готов к рассмотрению» означает отсутствие замечаний в полученном журнале, не одобрение торговой операции.

Автотест `test_dispatcher_rejects_stale_requests_and_exports_all_revisions` исполняет фактический JavaScript страницы в Node: переставляет ответы прогнозов/журналов, проверяет устаревшие ошибки, недоступность журнала, очистку и CSV. При отсутствии Node этот дополнительный тест пропускается; Python-сценарий от Node не зависит.

## Демонстрация на 3–4 минуты

1. Открыть `http://localhost:8000`, выбрать выпуск. Объяснить момент t0, 48 часов, нормализованную мощность и статус.
2. Раскрыть происхождение: источник, поле dayN, ограничения правила доступности. Показать CSV всех ревизий.
3. Сравнить сплошную линию и пунктир; назвать число обновлённых часов и максимальный сдвиг в процентных пунктах.
4. Показать журнал решений и блок «Поведение при сбоях». Это сохранённые результаты экспериментов; для повторного запуска: `uv run python -m app.cli faults` (перезаписывает артефакт эксперимента).
5. Показать метрики против базовых моделей, доверительный интервал эффекта пересчёта и ограничения. Денежная оценка сценарная, не измеренная экономия.
6. Показать `result.txt` полного smoke и соответствующий коммит. Запасной вариант — локальная страница и готовые артефакты; видео в репозитории пока нет.
