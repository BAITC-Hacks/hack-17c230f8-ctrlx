# Журнал проверок

Что проверяется, чем и с каким результатом. Владелец файла — `ansar`.

## Команды

```bash
uv run pytest -q          # все тесты
uv run ruff check .       # линтер
scripts/smoke.sh          # свежий clone с GitHub → install → тесты → запуск → основной сценарий
```

`scripts/smoke.sh` проверяет **то, что лежит на GitHub**, а не рабочую копию: он клонирует репозиторий заново в временную папку. Если есть незапушенные коммиты или незакоммиченные правки, скрипт предупреждает — в проверку они не попадают. Основной сценарий берётся из `SMOKE_PATH` (по умолчанию `GET /api/forecast/2026-01-31`) и совпадает с тем, что README предлагает эксперту.

## Проверки без автотестов

- **Правило утечки глазами.** На графике полоса p10–p90 окрашена по свежести прогноза: `day1` — плотная заливка, `day2`/`day3` — штриховка. Переход виден на 18-м часе от `t0` — ровно там, где правило запрещает более свежий прогон. Если бы в расчёт попала фактическая погода, полоса была бы однородной.
- **Пересчёт при обновлении данных.** Выпуск с ревизией 1 рисуется сплошной линией, а то, что он заменил, — пунктиром, с отметкой «пересчёт t0+12 ч». Видно, на сколько изменился прогноз.
- **Работа без ключей.** `/api/health` отдаёт `"mode":"demo"`, на странице значок `DEMO`. Ни одно число прогноза от LLM не зависит.

## Известные расхождения

- В сводке из `report.md` строка «Предупреждения: 6» считает **часы**, а блок на странице «Шаги агента с замечаниями: 1» считает **шаги лога**. Это разные сущности, не ошибка; подписи разведены, чтобы числа не читались как противоречие.
