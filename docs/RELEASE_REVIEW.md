# Итог аудита первого этапа — WindCast Agent

Срез проверки: 23.09.2026. Документ связывает правила, требования, архитектуру и
измеренные результаты. Подробности решения — [SOLUTION.md](SOLUTION.md), числа и
границы применимости — [METRICS.md](METRICS.md), устройство агента —
[AGENTIC.md](AGENTIC.md). Последние интеграционные проверки — [TESTING.md](TESTING.md).

## Решение для пользователя

WindCast помогает диспетчеру двухтурбинной ВЭС получить почасовой прогноз на 48
часов, увидеть неопределённость и понять причину пересчёта или резервного режима.
Оперативный план и черновик суточной заявки разделены. Все результаты можно
проследить до выпуска, ревизии, допустимого погодного поля и журнала решений.

Числовое ядро работает без LLM и личных аккаунтов. Для первого этапа это готовый
воспроизводимый прототип: эксперт может пересчитать февраль и проверить результат
по CSV, API, интерфейсу и журналам. Интеграции с настоящим торговым контуром нет.

## Архитектурные решения и исправления аудита

1. Один оркестратор обслуживает CLI и API. UI читает те же артефакты, поэтому
   результат графика можно проверить независимо от интерфейса.
2. Модель оценивает мощность; оркестратор выбирает допустимые входы и резервные
   ветки. История обоих слоёв сохранена, их вклад измеряется отдельно.
3. Признаки округляются до 12 десятичных знаков одинаково при обучении и
   прогнозе. Причина: отличие косинуса на один машинный шаг между macOS/Windows
   переключало ветку дерева, меняя мощность турбины на 9 процентных пунктов.
   Модель переобучена; регрессионные проверки имитируют такие расхождения.
4. Устранено смешение обучающей и калибровочной информации: квантильные признаки
   строятся до calibration, перекрывающиеся целевые часы исключены. Модель,
   метрики, прогнозы и сценарии после исправления пересчитаны.
5. Метка станции требует факта обеих турбин. Пропуски не заполняются вымышленной
   выработкой; погодный ветер при полном отказе источника может быть `null`.
6. Исключения и недопустимые числа основного и резервного расчёта проходят общую
   ограниченную лестницу. Недопустимая климатология не публикуется; неуспешный
   внутрисуточный пересчёт сохраняет исходный выпуск.
7. Запись одного выпуска защищена блокировками, подготовкой файлов и атомарной
   заменой; обычная ошибка записи восстанавливает предыдущие файлы. Это не
   транзакционная база и не гарантия единой транзакции всех файлов при отключении
   питания между заменами.
8. Частичный backtest сохраняет отдельный файл диапазона. Итоговый февральский
   CSV требует полного покрытия 672 часов и записывается атомарно; ошибка или
   обратный диапазон не заменяют его неполным результатом.
9. LLM-супервизор получает только агрегаты, выбирает диагностические инструменты
   и оставляет `accepted`/`review`. Обязательные проверки имеют приоритет.
   Он не меняет числовой прогноз и не отправляет заявки. Ограничены раунды,
   инструменты, токены и время; при ошибке доступен детерминированный результат.
10. Внешний LLM API отложен пользователем. Тесты и `mode=demo` подтверждают офлайн
   поведение, но не успешный вызов настоящего провайдера. Для основного цикла ТЗ
   это не зависимость; live-проверка остаётся явно незакрытой частью R9.

## Проверенное качество и устойчивость

| Проверка | Результат |
|---|---|
| Январь 2026: nMAE модели / персистентности | 15,36 % / 30,66 % |
| Февраль 2025: nMAE модели / персистентности | 17,78 % / 33,86 % |
| Покрытие p10–p90 станции | 80,5 % / 82,0 %; средняя ширина 49,1 % / 58,2 % номинала |
| Поломки входа | 5 из 5 сценариев сохранили 48 допустимых часов прогноза |
| Опубликованный план против неизменённого GBM, январь | MAE 0,1519 против 0,1536; интервал эффекта пересчёта включает ноль |
| Чистый clone `0d36840`, macOS | `uv sync --frozen`, ruff и 155 тестов прошли |
| Повторный backtest этого клона | 55,86 с; все 29 CSV побайтно совпали с GitHub |
| Два последовательных POST /api/run | 200; по 82 строки и 9 шагов, одинаковый CSV; 5,61 с и 1,95 с |
| Выпуск внутри обучающего периода / неизвестный выпуск | 422 / 404 |

Установка зависимостей требует сети или заранее заполненного кэша пакетов.
После установки основной сценарий использует локальные данные. Время — замер
одного компьютера; результаты Windows и итоговой интеграции фиксируются отдельно.

Валидационные месяцы использовались при выборе решения. Факта февраля 2026 нет,
поэтому точность на нём не измерена. Пять искусственных сбоев показывают полноту,
а не точность при отказе. Историческая публикация погоды оценивается по принятому
консервативному правилу, без полного журнала доступности каждого прогона.
Сценарные суммы в тенге — расчёт по указанным допущениям, не измеренная экономия.

## Что показывать эксперту и сохранить для Demo Day

Основной сценарий: открыть выпуск → объяснить 48-часовой прогноз и интервал →
показать исходную и обновлённую ревизии → открыть причины действий агента →
пересчитать выпуск → сравнить модель с эталонами → показать отказ основного
источника и сохранение полного прогноза. Проверяемые числа и файлы уже доступны
без внешнего API. Дополнительная платформа должна показывать эти же данные.

Готовый краткий текст для описания решения:

> WindCast Agent автономно формирует почасовой прогноз выработки двухтурбинной ВЭС
> на 48 часов, контролирует допустимость архивной погоды, пересчитывает прогноз
> при обновлении данных и сохраняет журнал причин каждого решения. В репозитории
> находятся 28 последовательных выпусков, план на весь февраль 2026, модель,
> погодный кэш и проверки отказов. Основной сценарий воспроизводится без API-ключей.

Путь развития после хакатона: сохранять конкретные погодные прогоны и реальные
времена их публикации; получать свежую SCADA для проверки дрейфа; валидировать на
независимом сезоне и дополнительных ВЭС; затем подключать согласование заявки и
эксплуатационный мониторинг. Эти возможности не выдаются за текущую реализацию.
